# Full Ontology & End-to-End Flows

## Core ontology

The system is organized around **Business Context**.

```text
IntegrateWise
  ↓
SpineWorkspace
  ↓
Business Context
  ↓
Spine Fabric
  ↓
Projection / Context Assembly
  ↓
Human Workbench + Twin Workbench
  ↓
Shared Work
  ↓
Work Allocation
  ↓
Human / AI / Agents
  ↓
Communications Bridge
  ↓
Governance
  ↓
Capability
  ↓
Execution
  ↓
Source Systems
  ↓
Re-ingestion
  ↓
Reconciliation
  ↓
Knowledge / Organizational Memory
  ↓
Continuity
```

## Three canonical flows

### 1. Business Context Ingestion & Synthesis

Source systems → Connectivity → Loader → Normalization → Semantic Synthesis → Entity/Relationship Resolution → Business Context → Spine Fabric.

### 2. Human–AI Work

Spine Fabric → Projection/Context Assembly → User Workbench \+ AI Sandbox → Twin → Shared Work → Work Allocation → Human/AI/Agent → Governance → Execution.

### 3. Communication, Execution, Reconciliation & Knowledge Continuity

Human/Twin/Agent → Communications Bridge → Scoped Context → Capability → Governance → Execution → Source System → Actual State → Re-ingestion → Reconciliation → Updated Business Context → Triage → Governed Knowledge → Organizational Memory → Spine → Next Work.

## Core laws

1. Business Context is the center.
2. One organization has one canonical reality.
3. AI operates on bounded operational context.
4. Work is the primary coordination unit.
5. Capability defines what can be done; Execution Fabric defines how.
6. Governance controls consequential authority.
7. Reconciliation closes the execution loop.
8. Memory becomes organizational knowledge only through governed promotion.
